# Build an Agricultural AI Evidence Company

## The Business

Create an evidence firewall between agricultural AI outputs and institutional trust.

## Who Pays

Buyers of AI recommendations, farm software companies, lenders, insurers, processors, and regulators.

## The Incumbent Workflow Being Unbundled

AI vendors often ask customers to trust model outputs, prompts, benchmarks, and lineage inside one black-box product. This recipe separates model output from evidence, evaluation, and reliance.

## What Information Enters Your Product

Model inputs, model outputs, prompts, model versions, benchmark results, field observations, operator actions, reviewer decisions, and downstream reliance records.

## AgEvidence Primitives

Use `SourceRecord` for input custody, `Observation` for field facts, `ModelRun` for AI output lineage, `Evaluation` for benchmark and policy checks, `Determination` for bounded trust statements, and `RelianceEvent` for downstream use.

## Rails Screens To Keep

Keep model runs, evidence, evaluations, gaps, review, determinations, artifacts, verification, developer keys, schemas, OpenAPI, logs, and webhooks.

## Rails Screens To Delete

Remove methane-specific vocabulary and any program pages that do not map to model assurance.

## What You Rename

Rename ProgramProfiles to model assurance profiles, gaps to assurance failures, artifacts to model evidence reports, and reliance events to institutional-use records.

## What You Build Yourself

Build model connectors, benchmark runners, lineage capture, prompt and dataset governance, and buyer-specific policy profiles.

## First API Integration

Record one model run with source commitments and output metadata.

## First Evidence Artifact

Issue a model evidence report bounded to one model version, input set, and benchmark profile.

## First External Verifier

Let a buyer verify the report manifest and evidence commitments independently from the AI vendor dashboard.

## Proprietary Moat

Benchmark design, model-risk expertise, distribution into buyers of agricultural AI, and integrations with AI vendors.

## Keep Interoperable

Source records, model runs, evaluations, determinations, artifacts, verification results, and reliance events.
