# Startup Recipes

Startup recipes show how to turn the Rails reference app into a focused agriculture company without fragmenting the shared evidence layer.

Use the same pattern for every vertical:

- The business
- Who pays
- The incumbent workflow being unbundled
- What information enters your product
- What AgEvidence primitives represent it
- Which Rails screens you keep
- Which Rails screens you delete
- What you rename
- What you need to build yourself
- Your first API integration
- Your first evidence artifact
- Your first external verifier
- What becomes your proprietary moat
- What should remain interoperable

## Principle

Do not create incompatible evidence islands unless there is a compelling reason. Keep shared receipt formats, provenance, artifact manifests, verification results, and reliance events compatible. Differentiate above that layer.
